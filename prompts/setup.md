# Промпт агенту-установщику

Передайте агенту ссылку на репозиторий и текст ниже. Если известны проект, задача, план, число участников и разрешённый модельный бюджет, добавьте их в конец запроса. Если они уже есть в беседе, не заполняйте их повторно.

```text
Подключи DeLM board к моему проекту:
https://github.com/Diffuzmetall/delm-board

Нужен рабочий пользовательский сценарий с моей установкой Pi/Durable,
без зависимости от хоста автора. Доска и адаптер должны оставаться раздельными.

Прочитай README.md и AGENTS.md. Определи из установленного пакета,
его версии, команды запуска и доступного API, что у меня действительно есть:
1) приложение на публичном @earendil-works/pi-durable;
2) обычный публичный Pi CLI из @earendil-works/pi-coding-agent;
3) только потребность в самостоятельной доске.
Не считай эти варианты взаимозаменяемыми. Публичная проверенная версия — 1.4.0.
Не обещай совместимость неизвестного хоста только по номеру SDK.

Если это Durable SDK, следуй docs/durable-sdk.md: подключи factory к реальному
существующему registry приложения, сохрани его Harness, storage, scheduler,
модели, environment и hooks. Проверь эффективную рабочую папку и выбранные tools.
Не создавай второй owner, не патчи upstream и не устанавливай другой хост.
Если точка расширения приложения недоступна, назови точный blocker,
а не выдавай обычный Pi CLI за Durable. Продолжи независимую подготовку доски.

Если это Pi CLI, используй connect pi и официальный ExtensionAPI.
Подготовь точные отдельные команды участников с их workspace, расширением
и --session. Не подключайся к произвольной работающей TUI через выдуманный API.
Для локального Pi настрой PATH в каждом терминале участника.
Не исполняй весь вывод connect через eval: он содержит и пояснения.

Используй мои существующие авторизацию и правила доступа. Не запрашивай ключи
в чате и не выводи config.json, токены или историю сессий.
Не меняй глобальные настройки, чужие репозитории, SDK, permissions или guards.
Для самостоятельной доски не устанавливай Node/npm-зависимости без необходимости.

Используй заданный проект, утверждённую задачу и план. Выбери новый приватный RUN
вне проекта и клона DeLM. Не перезаписывай существующие файлы/привязки и не запускай
init для продолжения прежней работы. Если уже есть RUN, сначала проверь его состояние.
Если недостаёт цели, конкретной установки или разрешения на расходы, собери только
неустранимые вопросы одним коротким сообщением; всё доступное исследуй самостоятельно.

Установка репозитория, локальные обратимые настройки подключения и модельно-независимые
проверки разрешены этим запросом. Запуск живых моделей — только если уже согласованы
число участников, задача и пределы расходов. Иначе подготовь команды без их исполнения.
Этот запрос НЕ разрешает commit/push, публикацию, deploy, замену runtime или удаление данных.

Готово, когда:
- Python-доска открывает реальный проект и показывает согласованный состав участников;
- адаптер использует правильную публичную точку входа, не хост автора;
- повторная подготовка сохраняет привязки и не создаёт лишних сессий/ввода;
- безопасный smoke подтверждает чтение/изменение тестовой задачи в отдельном RUN
  и snapshot/read/ACK; тестовые записи не загрязняют рабочую доску;
- если модельный запуск разрешён, результат проходит через реальную беседу:
  действие на доске, событие, нужный waiter, чтение receipt и явный ACK;
- иначе живой запуск честно отмечен как не выполненный, а не как PASS;
- предоставлены команды продолжения, остановки и безопасного отключения.

В результате кратко укажи:
фактический runtime/версию и выбранный адаптер; что локально изменено;
workspace и RUN без секретов; точные команды backend/view/участников;
свежие проверки, ограничения и действительно недостающие действия с моей стороны.
Не обещай exactly-once для Pi follow-up. Для Durable соблюдай cancel/drain перед uninstall.
```

## Что этот промпт не делает

Он не предоставляет агенту доступ к чужому компьютеру и не заменяет авторизацию провайдера. Отчёт «пакет установлен» не доказывает работу агентов. Для полного модельного smoke нужны явное разрешение и реальная установка; для предварительной проверки подходят изолированные фикстуры репозитория.
